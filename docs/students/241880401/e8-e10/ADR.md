# ADR：候选补丁在沙箱验证后才写回

## 背景与决定

固定 MD 报告须先与受测项目提交匹配。生成候选时保持源文件不变；先在独立副本中检查补丁可应用、构建、运行、头文件变化后增量构建以及缺失依赖重检，全部通过后才写回 Makefile。任意失败均拒绝并保留源文件字节。

## 声明风格和代价

直接依赖修改目标行；纯变量依赖修改变量定义；混合依赖保留变量引用并修改目标行。共享变量可能被其他目标引用，当前教学实现不做跨目标影响分析；复杂 Make 规则超出支持范围。每次沙箱构建与动态跟踪有时间开销，但便于保留可审计证据。

## 验证

`work/student-b-02/e10-B/` 中的 reject-test、accept、reject-patch 和 student-build-failure 分别记录测试失败、成功、坏补丁和编译失败；两个源文件副本提供逐字节对照。`recheck-buildchecker/` 保留真实动态重检证据。
